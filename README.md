# 麦麦大亨 · 后厨

> 一个用**真实麦当劳菜单**做的后厨做菜游戏。薯条要盯着油锅捞，可乐要按住按钮打到线上，汉堡要照着票子一层一层加料。
> 参赛项目 · 麦当劳程序员节创意开发大赛 · **非麦当劳官方产品**

![薯条站](docs/shot_fries.png)

---

## 这是什么

大部分"餐饮经营"游戏，你其实是个经理：看报表、调价格、点按钮。后厨那一摊事被一个进度条糊弄过去了。

这个反过来——**你就是那个站在后厨的人**：

- 订单从门口挂上来，一张一张排在顶部的票架上
- **五座工位**，一屏只站一个，靠 tab 切：薯条站 / 炸物站 / 饮料站 / 煎区 / 组装站
- 每一份都得你亲手做出来，做得准不准，直接决定小费和废品率
- 汉堡不是点两下就出来的：**先去煎区把肉饼两面煎好**，才有得组装
- 顾客有耐心条，耗完了就走人，钱和口碑一起没

一天 60 秒，经营 5 天。从 ¥1000 起步，房租每天涨 ¥15，跑单要赔钱，最后按现金余额评 S / A / B / C / D。

**菜单、价格、汉堡配方、营养数据全部来自麦当劳 MCP 实时拉取**——这家店今天卖什么，游戏里就卖什么。换一家店、换一天，内容都不一样。

## 怎么玩

### 一张单的完整流程

```
看票  →  切到对应工位  →  选品  →  制作  →  成品落到出餐架  →  点订单上的「出餐」
```

出餐架是五个工位共用的，8 格，满了就放不下。哪张单凑齐了，点哪张。

### 五座工位

| 工位 | 你要做的 | 怎么搞砸 |
|---|---|---|
| **薯条站** | 3 个油槽各自计时。进度条进绿区，点一下捞出 | 没炸透就捞＝扔了；过了头就焦，得再点一下清锅 |
| **炸物站** | 下锅之后**中途要点一下抖篮**，再到绿区捞出 | 不抖＝粘连，质量封顶 45 分；抖早了没用；过火就焦 |
| **饮料站** | 按住杯子注液体，液面进绿区松手 | 没到线下＝倒了；超过上线＝溢了。都算废品 |
| **煎区** | 放肉饼 → 第 1 面到绿区**翻面** → 第 2 面到绿区**起锅**，进保温盘（4 格） | 两面都到点没动＝焦；保温盘满了再起锅＝扔掉 |
| **组装站** | **先有肉饼**，再照着票面顺序逐层点配料，加满合上出餐 | 顺序错了抖一下，连错 2 次这份废掉；没肉饼出不了餐 |

![煎区](docs/shot_grill.png)

### 压力从哪来

- 油锅、炸篮、煎位同时在走，但你一屏只能看一个工位
- 薯条熟成窗口 3.3 秒、绿区只占 40%；炸物 3.4 秒；煎区每面 2.5 秒、两面都要盯
- 汉堡必须两块工序接力：煎区出肉饼 → 组装站才做得出来，肉饼断供整条线停摆
- 顾客耐心从第 1 天的 22 秒缩到第 5 天的 14 秒，客流间隔从 5.6 秒压到 4.0 秒
- 出餐架只有 8 格，而且**放凉会掉质量**——出锅 10 秒后开始，每秒掉 5%

### 评分

绿区正中出品 = 完美，小费 +20%；偏一点 = 良好，+10%。堡的分数由「配料手稳」和「肉饼火候」两部分合成。
废品会真实扣掉原料成本；跑单每人赔 ¥9；房租每天涨 ¥15（¥45 → ¥105）。
评级线：S ≥ ¥1700、A ≥ ¥1500、B ≥ ¥1250、C ≥ ¥1050。

## 数据从哪来

| 游戏里的东西 | 来自哪个 Tool |
|---|---|
| 门店名、地址 | `query-nearby-stores` |
| 13 款商品的名称与价格 | `query-meals`（116 个在售项里挑出的单品） |
| 6 份汉堡的真实配料与顺序 | `query-meal-detail` 的 `modification`（`selectedQuantity > 0`） |
| 热量/蛋白/脂肪/碳水/钠 | `list-nutrition-foods`（158 条） |
| 今日活动 | `campaign-calendar` |

拉回来的数据先落成 `data/snapshot.json`，再注入 `game/index.html` 的内嵌数据块。**游戏本身不联网**，双击就能玩，但内容是真数据。

细节（包括 MCP 返回结构和文档不一致的几处）写在 [MCP_INTEGRATION.md](./MCP_INTEGRATION.md)。

## 本地跑

### 只想玩

```bash
open game/index.html
```

就这样。单文件，零依赖，不装任何东西。

### 想验证数值改动

`tools/harness.js` 是 jsdom + 虚拟时钟的测试台，让机器人用真实点击跑完整 5 天，读日结面板的数字做现金守恒校验。

```bash
# 需要 jsdom（装在 WorkBuddy 的 node 工作区里）
NODE_PATH=~/.workbuddy/binaries/node/workspace/node_modules \
  node tools/harness.js game/index.html smart 16 80000

# 换瞎点机器人看下限
NODE_PATH=~/.workbuddy/binaries/node/workspace/node_modules \
  node tools/harness.js game/index.html dumb 16 80000
```

输出每天的服务率、完美单、废品、净利，最后给评级与守恒校验。判据写在 [BALANCE.md](./BALANCE.md)。

### 想换成自己附近的店

需要 Node 18+（要 `fetch`）和一个麦当劳 MCP Token（在 [open.mcd.cn](https://open.mcd.cn/mcp) 控制台申请）。

```bash
# 1. 配 Token（三选一）
export MCD_MCP_TOKEN=你的token
# 或写给文件：echo 你的token > tools/.mcd-token
# 或写进本机 ~/.workbuddy/mcp.json 的 mcd-mcp.headers.Authorization

# 2. 拉数据 + 注入游戏
node tools/pull-mcp.js --store 1421136

# 只想看看拉回来什么，不写文件
node tools/pull-mcp.js --dry
```

`--store` 换成你自己的门店编码即可。输出长这样：

```
▶ 拉取门店…   门店：麦当劳深圳腾讯总部园区一店餐厅（1421136）
▶ 拉取菜单…   在线商品 116 项
▶ 拉取营养表… 营养条目 158 条
▶ 拉取汉堡配料（6 次）…
  巨无霸 → 巨无霸酱、吉士、生菜、酸黄瓜、洋葱粒
✔ 写入 data/snapshot.json
✔ 已注入 game/index.html
```

### 接入方式

把 [mcp-config.example.json](./mcp-config.example.json) 里的 `YOUR_MCP_TOKEN` 换成自己的，粘到 WorkBuddy 的【自定义连接器 → 配置 MCP】，保存 → 启用。

## 设计取舍

**为什么不做"配货—库存—定价"那套？** 因为那是表格，不是后厨。真让人有"我在干活"的感觉的，是手上那 3.8 秒。

**为什么一屏只做一个工位？** 工位同屏时，压力来自"同时看五个倒计时"，那是注意力测试，不是手艺。Papa's 系列证明了：一次专注一个工位、切站有成本，才有节奏感。

**为什么数据要内嵌而不是每次 fetch？** 分发成本。在线版点开就玩，本地版双击就开，谁都不用先申请 Token。

**为什么全是 SVG + WebAudio，没有一张图、一个音频文件？** 单文件的代价是体积，收益是"发给谁都能立刻打开"。薯条、可乐、汉堡、顾客脸全是手写 SVG；音效是 WebAudio 现场合成的方波和噪声。

## 已知限制

- 只有 5 天，没有存档，没有排行榜
- 活动日历目前只展示，不参与结算
- 原料成本按售价 35% 估算（MCP 不提供成本数据），是游戏数值不是真实财务数据
- **煎区用的是"通用肉饼"**：MCP 只提供成品汉堡的配料表，不提供中间产物，所以游戏把"煎肉饼"抽象成一道工序，不区分牛/鸡/鱼部位——这是玩法简化，不是数据造假；商品、价格、配料、营养仍然 100% 来自 MCP
